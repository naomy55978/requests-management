# מערכת לניהול פניות – Frontend

צד הלקוח של מערכת ניהול הפניות: אפליקציית Angular 22 עם Angular Material, בעברית ועם פריסת RTL, שעובדת מול ה־REST API של ה־Backend.

> התכנון, ההחלטות וה־Issues נמצאים ב־[requests-management-docs](https://github.com/naomy55978/requests-management-docs) – נקודת הכניסה לפרויקט. ה־Backend נמצא ב־[requests-management-be](https://github.com/naomy55978/requests-management-be).

## דרישות

- **Node.js** בגרסה `^22.22.3` או `^24.15.0` (כך ש־Angular 22 דורש). בפרויקט יש `.nvmrc` עם הערך `24`. Node 20 לא מספיק.
- ה־**Backend** חייב לרוץ על `http://localhost:5084` (ראו את ה־README של [requests-management-be](https://github.com/naomy55978/requests-management-be)).

## הרצה

```bash
npm ci
npm start
```

האפליקציה תהיה זמינה ב־http://localhost:4200.

### ה־Proxy

שרת הפיתוח מעביר כל בקשה ל־`/api/...` אל ה־API (`proxy.conf.json`, ברירת מחדל: `http://localhost:5084`). מבחינת הדפדפן הכול מגיע מאותו Origin, ולכן אין צורך ב־CORS בצד השרת. אם ה־API רץ בכתובת אחרת – יש לשנות את `target` בקובץ `proxy.conf.json`.

אם ה־API לא רץ, האפליקציה תציג הודעה "אין חיבור לשרת" עם כפתור "נסה שוב".

## התחברות ומה יש במסכים

משתמש לדוגמה: `dana.cohen` / `Demo123!`. מסך ההתחברות אינו מציג פרטי התחברות.

- **התחברות** – הטוקן נשמר ב־`sessionStorage` ונמחק עם סגירת הלשונית. כשפג תוקפו, המשתמש מועבר חזרה להתחברות ומשם לדף שבו היה (רק לנתיב פנימי).
- **לוח בקרה** – מסך הפתיחה אחרי ההתחברות: סה״כ פניות, ספירה לפי סטטוס ולפי עדיפות, והארגונים עם הכי הרבה פניות פתוחות. הסיכום נטען בכל כניסה למסך, ויש כפתור "רענן". ליד הכותרת תג שקט עם זמן הטעינה, ובסיכום גם אם השרת ענה מה־Cache (`HIT`/`MISS`).
- **ניווט** – בסרגל העליון שני קישורים, "לוח בקרה" ו־"פניות", והמסך הפעיל מסומן. שניהם דורשים התחברות; מי שאינו מחובר מועבר להתחברות וחוזר למסך שביקש.
- **רשימת פניות** – כל הדפדוף, המיון, הסינון והחיפוש מתבצעים בשרת. סינון לפי סטטוס, עדיפות, ארגון, מטפל (או "ללא מטפל") וטווח תאריכי יצירה. טקסט חופשי נשלח לשרת 300 מילי־שניות אחרי ההקלדה האחרונה, וחיפוש דורש לפחות 2 תווים.
- **עדכון סטטוס** – מתפריט השורה (רק מעברים מותרים; אישור לפני "הושלמה"), עדכון מרוכז של שורות מסומנות בעמוד הנוכחי עם תוצאה לכל פנייה, והיסטוריית סטטוס בשעון מקומי. אם פנייה עודכנה בינתיים על ידי משתמש אחר (409) – השורה מתרעננת ומוצגת הודעה.
- **ביצועים** – כפתור "ביצועים" בסרגל פותח, בראש התוכן, פאנל עם הבקשות האחרונות וזמניהן (מכותרת `Server-Timing`). הפאנל סגור כברירת מחדל.
- **מצבי תצוגה** – טעינה, אין תוצאות (עם כפתור "נקה סינון") ושגיאה (עם כפתור "נסה שוב").

> שדות התאריך נבחרים מלוח השנה בלבד: ה־Native Date Adapter אינו מפרש תאריך שהוקלד בפורמט `dd/MM/yyyy`, ולכן ההקלדה חסומה כדי לא ליצור טווח שגוי.

## בדיקות ואיכות קוד

```bash
npm test -- --watch=false   # בדיקות יחידה (Vitest)
npm run lint                # ESLint (angular-eslint)
npm run build               # בנייה לפרודקשן (dist/)
```

ה־CI ב־GitHub Actions מריץ את שלושתם על כל Push (`.github/workflows/ci.yml`, Node 24).

## מבנה הקוד

```
src/app/
  core/       שירותים ללא תצוגה: גישה ל־API, התחברות, תרגום תוויות והודעות שגיאה
  shared/     רכיבי תצוגה קטנים לשימוש חוזר
  features/   המסכים
```

כל Component מחולק לשלושה קבצים נפרדים (`*.component.ts`, ‏`*.component.html`, ‏`*.component.scss`) – אין template או styles Inline, וה־Lint אוכף זאת.
